# 개인별 이동수단과 공평한 중간지점 추천

사용자는 기존 결과 화면을 유지하고 출발지별 이동수단 선택만 추가하는 범위로 구현, 테스트, PR 생성을 승인했다.

- 결과 화면의 배치, 지도, 비교, 투표, 확정 흐름은 유지한다. 필요하면 기존 설명 문구와 이동수단 표기만 맞춘다. 지도 제공사 표시 정책 정리는 별도 작업이다.
- 출발지 입력에서 대중교통, 자동차, 도보를 선택한다. 개인 검색과 함께 검색 모두 선택을 저장하고 전송한다. 기존 공통 이동수단 입력은 개인별 선택으로 대체하고 위치/시간 기준은 유지한다.
- 기존 요청/저장 데이터의 이동수단 누락은 기존 공통 옵션으로 해석하고, 그것도 없으면 대중교통이다. 명시적인 잘못된 개인 이동수단은 거부한다.
- Google 대중교통, Kakao 자동차/도보 및 장소 검색을 사용한다. 자동 수단 변경이나 가짜 시간 보충은 하지 않는다. 모든 참가자의 유효한 경로가 있어야 추천한다.
- 현재 출발 기준으로 새 경로를 구한다. 기존 30일 경로 캐시는 시간 기준 비교에 쓰지 않는다. 동일 요청 안의 동일 좌표/수단 호출만 합친다. 장기 저장/지도 정책 전체 개편은 범위 밖이다.
- 수도권은 서울·경기·인천이다. 기존 역/지역 데이터에서 중심 부근, 서로 다른 권역, 도보 참가자 근처를 포함해 후보를 고른다. 대중교통/혼합은 기존 기본 8개·최대 12개, 자동차 단독은 기존 16개·최대 20개 상한을 유지해 호출 폭증을 막는다.
- 시간 기준은 전체 참가자에게 열등한 후보를 먼저 제외한다. 최선의 최장시간 +300초 이내 후보를 우선하고, 그 안에서는 시간 격차 → 최장시간 → 평균시간 → 대중교통 환승/도보 → 목적별 장소 점수 → 안정적인 장소 식별 순서로 정렬한다. 범위 밖 후보는 최장시간부터 정렬한다.
- 위치 기준은 기존 거리 점수와 시간 불균형 보정을 유지한다. 새 정렬 결과를 기존 recommend_score 숫자 필드로 전달해 결과 UI/공유 RPC를 재구성하지 않는다.
- 약속 날짜 선택, 자전거, 새 API 제공사, 지도 개편, 실제 서비스 배포/병합은 포함하지 않는다.

검증은 불균형 그룹, 전체 열등 후보, 5분 경계, 입력 순서, 부분 실패, 혼합 수단, 기존 요청/공유 결과, 실 SQL RPC, UI 입력을 다룬다. 외부 응답은 공식 스키마 fixture로 검증하며 실제 API 응답을 검증한 것으로 표현하지 않는다.

검토한 대안은 전체 화면 개편, 전체 API 교체, 기존 화면 유지와 알고리즘 개선이다. 사용자가 마지막 방식을 선택했다. 5분 허용 폭과 후보 공간 분산은 초기 정책이며 실제 이동 사례에 따라 조정 가능하다.
