# 검색 유입 개선

승인된 목표는 `중간지점 찾기`, `약속장소 정하기`와 관련된 검색에서 OKNAWA를
발견하고 실제 모임에 사용할 수 있게 만드는 것이다. 순위나 수익을 보장하지 않는다.
기존 홈 디자인과 입력·추천·투표·확정 흐름은 유지한다.

## 선택한 접근

기술 설정만 수정하면 서비스의 구체적인 용도를 전달하기 어렵다. 반대로 키워드별
페이지를 먼저 늘리면 유사한 내용과 유지 비용이 생긴다. 홈을 대표 검색 페이지로
정비하고, 등록 후 실제 검색어에 따라 고유한 안내 페이지를 추가하는 접근을 택한다.
이는 앞서 제안한 단계별 범위에 대한 사용자의 `좋아. 진행하자.` 승인을 따른다.

## 이번 구현

- Next.js Metadata API로 제목·설명·공유 정보·canonical을 서버 HTML에 제공한다.
- 대표 검색 주소는 `https://www.oknawa.com`이다. 모임 입력·초대·결과에는 noindex를
  적용하고 robots.txt는 수집을 허용해 해당 지시를 읽을 수 있게 한다.
- sitemap에는 실제 공개 설명이 있는 홈만 넣는다. WebSite 구조화 데이터에는
  서비스 이름과 주소를 담고 근거 없는 리뷰·평점·가격·SearchAction은 넣지 않는다.
- 홈 하단에 사용법, 교통수단과 추천 기준, 예상 시간의 한계, 기존 장소 모이기를
  설명한다. 클릭 없이 서버 HTML에 포함하되 상세 FAQ는 기본 접힘으로 제공한다.
- 지도·주소 검색 화면에서만 Kakao SDK를 로드한다. 홈페이지 진입 시는 요청하지
  않고 해당 화면으로 이동하거나 직접 접속할 때 기존 로딩·오류 처리를 보존한다.
- 사용자의 요청으로 로그인된 브라우저에서 발급받은 공개 소유권 인증값을 기본값으로
  반영한다. 선택적 환경변수로 교체할 수 있으며 로그인 비밀번호나 API 키는 포함하지 않는다.
- 빌드 결과 검사와 모바일 브라우저 검증으로 SSR, 메타 중복, 크롤링 정책,
  기존 앱 흐름 및 신규 홈 설명의 접근성을 확인한다.

## 등록 이후

사용자가 직접 등록 작업도 위임하여 로그인된 브라우저로 Google 속성 추가와 양쪽
HTML 인증값 발급까지 진행했다. 운영 배포 후 소유권 확인과 사이트맵 제출을 이어간다.
대표 도메인 영구 리다이렉트는 이번 PR에 포함하지 않는다.
운영 배포와 검색 색인은 별개다. 실제 검색량·순위·실사용 성능 수치가 없는 현재는
이를 추정치로 채우지 않는다. 검색어별 노출·클릭·CTR과 앱 이용을 함께 보며 개선한다.
