# 검색 노출 운영

검색 유입은 홈페이지 `https://www.oknawa.com`으로 모읍니다. 첫 목표 검색어는
`중간지점 찾기`, `약속장소 정하기`, `약속 장소 추천`입니다. 현재 검색량이나
순위는 확인하지 않았으며, 검색 설정을 개선해도 상위 노출이 보장되지는 않습니다.

## 검색 의도와 콘텐츠 방향

2026-11-05 공개 웹 검색으로 `중간지점 찾기`, `약속장소 정하기 중간지점`,
`대중교통 중간지점 찾기`를 조사했습니다. 개인화·검색 엔진·기기에 따라 결과가
달라지므로 아래는 경쟁 페이지의 내용 비교이며 구글/네이버 순위표가 아닙니다.

| 검색 의도 | 우선 검색어 | 이번 대응 |
| --- | --- | --- |
| 바로 도구를 사용 | 중간지점 찾기, 중간 장소 찾기 | 홈 제목·설명과 기존 직접/함께 입력 동선 |
| 여러 명의 이동 부담 비교 | 여러 명 중간지점, 대중교통 중간지점 | 참가자별 교통수단, 시간/위치 기준 설명 |
| 친구들과 장소 결정 | 약속장소 정하기, 약속 장소 추천 | 모임 링크·후보 비교·투표·주변 장소 사용법 |
| 이미 정한 장소까지 이동 | 모임 장소 이동시간 | 기존 정해진 장소로 모이기 기능 안내 |

확인한 자체 서비스 페이지:

- [handii](https://where2meet.handii.net/): 출발역 입력 도구와 계산 기준,
  포함하지 않는 시간, 데이터 한계를 함께 설명합니다.
- [꿀툴](https://kkultools.com/meet): 사용법, 약속 상황, 교통수단, FAQ를 도구와
  함께 제공합니다. 이 페이지의 설명은 해당 서비스의 주장으로, 정확도를 검증한 것은 아닙니다.
- [밋미들](https://meetmiddle.co.kr/): 거리/시간 기준과 주변 장소·모바일 사용 FAQ를
  제공합니다. 지역 페이지 수나 문장 길이를 그대로 따라 하지 않습니다.

OKNAWA는 가입 없는 직접/함께 입력, 참가자별 대중교통·자동차·도보,
후보 비교와 투표를 실제 코드에 있는 기능으로 설명합니다. 경쟁사보다 정확하다거나
전국 어디든 최적의 장소를 찾는다는 표현, 계산하지 않은 예시 이동시간은 쓰지 않습니다.
별도 안내 페이지는 홈과 다른 질문을 충분히 설명할 때만 추가합니다. 지금은 홈과
중복되는 `/midpoint`, `/meeting-place` 페이지를 만들지 않습니다.

## 공개 페이지와 모임 페이지

- 홈페이지에 검색 제목·설명, canonical, 공유 메타데이터, WebSite 구조화 데이터,
  실제 서비스 이용 안내를 제공합니다. 기존 입력 버튼과 모임 흐름은 유지합니다.
- `/robots.txt`가 `/sitemap.xml`을 안내합니다. 사이트맵에는 홈페이지만 넣습니다.
- 입력·초대·결과 페이지는 공통 `noindex, nofollow`를 상속합니다. 공개 안내 페이지를
  추가하면 해당 페이지에서만 검색 허용 및 canonical을 지정하고 사이트맵에 넣습니다.
- robots.txt로 모임 페이지 수집을 막지 않습니다. 검색로봇이 페이지의 noindex를
  읽을 수 있어야 합니다. noindex는 접근 제한이 아니며 기존 링크 공유 권한을 바꾸지 않습니다.
- 대표 도메인은 코드의 `src/config/seo.ts`에서 관리합니다. 로컬/미리보기용
  `NEXT_PUBLIC_BASE_URL`이 검색용 canonical이나 사이트맵에 섞이지 않게 분리했습니다.
- 지도 SDK와 카카오 공유 SDK는 `/search`, `/meeting`, `/result`에서만 로드합니다.
  홈에서는 요청하지 않으며 기존 이미지 크기 지정과 우선 로딩을 유지합니다.

## 배포 후 등록

1. 운영 홈페이지, `/robots.txt`, `/sitemap.xml`이 모두 200인지 확인합니다.
2. Google Search Console에서 DNS 관리가 가능하면 `oknawa.com` 도메인 속성과
   TXT 인증을 권장합니다. 프로토콜·서브도메인을 함께 볼 수 있습니다. DNS 접근이
   어렵다면 `https://www.oknawa.com/` URL 접두어 속성을 등록합니다.
   이번에는 로그인된 계정에서 URL 접두어 속성을 추가하고 HTML 인증값을 발급받아
   `src/config/seo.ts`에 반영했습니다. 배포 후 같은 계정에서 소유권 확인을 완료합니다.
3. 네이버 서치어드바이저에도 같은 주소를 등록합니다. HTML 태그의 `content` 값을
   발급받아 같은 파일에 반영했습니다. 배포 후 소유권 확인을 완료합니다.
   확인 값은 공개 HTML에 출력하는 값이며 로그인 비밀번호나 API 키가 아닙니다.
4. 두 도구에 `https://www.oknawa.com/sitemap.xml`을 제출합니다. 구글은 URL 검사에서
   홈페이지 색인 생성을 요청하고, 네이버는 웹페이지 수집 요청으로 홈페이지를 제출합니다.
5. Vercel Domains에서 `oknawa.com` → `www.oknawa.com` 리다이렉트를 영구 308로
   설정하는 것을 권장합니다. 2026-11-05 운영 확인 당시 307이었으며, 이번 코드 작업은
   Vercel 도메인 설정을 변경하지 않습니다.

계정 변경 등으로 인증값을 교체할 때는 해당 상수를 수정하거나 Vercel Production 환경변수
`GOOGLE_SITE_VERIFICATION`, `NAVER_SITE_VERIFICATION`으로 덮어쓰고 재배포합니다.
등록·사이트맵 제출은 코드 배포만으로 자동 완료되지 않습니다.
미리보기 배포의 공개 검색 노출은 Vercel의 배포 보호 및
`X-Robots-Tag` 설정도 확인하세요.

2026-11-05 등록 상태: Google URL 접두어 속성 추가와 양쪽 HTML 인증값 발급까지
진행했습니다. 코드의 운영 배포가 선행되어야 하므로 소유권 확인 완료, 사이트맵 제출,
홈페이지 수집 요청은 아직 진행하지 않았습니다.

## 검색 성과 확인

배포일과 등록일을 기록하고 매주 같은 기간으로 구글 실적·네이버 노출/클릭을 비교합니다.
색인 여부, 실제 유입 검색어, 노출수, 클릭수, CTR을 먼저 봅니다. 평균 순위는
검색어·국가·기기별로 확인하며, 개인 브라우저의 검색 결과를 전체 순위로 간주하지 않습니다.

브랜드 검색어(`오케이나와`, `oknawa`)와 일반 검색어를 분리하고, 첫 28일을 기준선으로
기록합니다. 첫 달 목표는 특정 순위 약속이 아니라 색인 완료와 비브랜드 노출 확인입니다.
표본이 적은 CTR 변화로 제목을 자주 바꾸지 않고, 다음과 같이 판단합니다.

| 관찰 | 다음 확인/작업 |
| --- | --- |
| 색인되지 않음 | URL 검사로 수집 가능 여부, 선택된 canonical, noindex, 응답 상태 확인 |
| 색인은 됐지만 원하는 검색어 노출이 적음 | 검색 의도와 본문을 비교하고 필요한 고유 안내를 보강 |
| 노출되지만 클릭이 적음 | 검색 결과 제목/설명, 해당 검색어의 순위·기기·경쟁 결과를 함께 비교 |
| 클릭되지만 서비스를 시작하지 않음 | Vercel Analytics의 유입 경로와 입력 화면 방문, 모바일 흐름 확인 |

현재 Vercel Analytics는 기본 페이지 방문 분석이며 계산 완료율까지 증명하지 않습니다.
개별 주소·이름·모임 ID를 분석 이벤트에 넣지 않습니다. 추가 전환 이벤트나 유료 분석은
별도 범위로 정합니다. 외부 소개나 자연스러운 추천 링크가 생기는지도 함께 보되,
링크 구매·자동 게시·허위 사용 후기는 하지 않습니다. 코드만으로 외부 신뢰를 만들 수는 없습니다.

모바일 성능은 등록 후 Search Console 실사용 데이터가 생기면 LCP·INP·CLS를 확인합니다.
2026-11-05 PageSpeed 공개 API는 429로 응답하여 점수를 확보하지 못했습니다.
로컬 브라우저 검사나 빌드 크기를 실사용 성능 점수 또는 검색 순위 향상으로 보고하지 않습니다.

몇 주간 수집된 검색어를 보고 실제 질문에 답하는 안내를 보강합니다. 예를 들어
`친구들 중간지점 찾기`, `대중교통 중간지점`, `여러 명 약속장소 정하기`에 대한
사용법이 후보입니다. 검색어만 바꾼 유사 페이지나 근거 없는 지역별 추천 순위를
대량으로 만들지 않습니다.

## 검증

`pnpm agent:harness`와 CI는 빌드 후 `node scripts/check-seo.mjs`를 실행합니다.
정적 빌드와 실제 HTTP 응답을 일반 브라우저·Googlebot·Yeti로 검사하여 검색 허용/제외,
중복 메타태그, canonical, 본문 안내·FAQ, 구조화 데이터, robots.txt와 sitemap.xml을
확인합니다. 정적 메타데이터가 동적 모임 URL에서도 최초 head에 포함되도록
`htmlLimitedBots`로 메타데이터 스트리밍을 끕니다. 검사기는 Next.js와 동일하게
production 환경변수 파일을 읽습니다. 지도 SDK 초기화와 기존 모임 흐름은
기존 앱 테스트 및 브라우저 확인으로 검증합니다. 로컬 검사로 실제 검색 색인이나
운영 계정 등록 완료를 증명할 수는 없습니다.

[noindex와 크롤링](https://developers.google.com/search/docs/crawling-indexing/block-indexing),
[네이버 사이트맵 제출](https://searchadvisor.naver.com/guide/request-feed).
