# 함께 입력하는 방의 추천 복구

추천 시작과 참가자 등록은 같은 방 행을 잠근다. 시작 RPC가 반환한 참가자 전원으로 계산하며, 추천 진행 중이거나 완료된 방에는 추가 등록을 허용하지 않는다. 늦은 참가자는 기존 안내창에서 새 모임 링크를 요청하도록 안내받는다. 실패한 방에서는 다시 등록하고 추천할 수 있다.

추천 실행은 시작 시각부터 5분 동안 유효하다. 탭 종료나 새로고침으로 끝내지 못한 실행은 다음 상태 조회에서 실패로 전환되고, 기존 추천 버튼으로 다시 시도할 수 있다. 시작·등록 요청도 만료를 직접 확인하므로 먼저 상태를 조회할 필요가 없다. 완료·실패 처리는 방장 키와 실행 ID를 모두 확인하며, 이전 실행의 늦은 응답은 새 실행이나 완료된 결과를 바꾸지 않는다. 실행 ID와 방장 키는 공개 방 조회에 포함하지 않는다.

기존 `room` 저장 형식은 유지하며 같은 브라우저에서 만든 방의 권한을 방별로 보관한다. 자신의 초대 링크로 등록하거나 다른 방을 방문해도 기존 방의 권한을 잃지 않는다. 다른 참가자가 만든 방에는 권한을 부여하지 않는다. 브라우저 데이터를 삭제하거나 다른 기기를 사용하는 경우의 권한 복구 기능은 포함하지 않는다.

## 배포

- `20261029090000_recover_room_recommendations.sql`과 프런트엔드 변경을 함께 배포해야 한다. main 병합 시 기존 Supabase Deploy와 Vercel 배포를 모두 확인한다.
- 이전 버전의 탭은 실행 ID를 보내지 않으므로 완료 요청이 거부될 수 있다. 이 경우 새로고침하고 다시 추천한다. 배포 전 시작된 실행도 상태 조회 시 복구된다.
- 프런트엔드가 DB보다 먼저 배포되면 이전 시작 응답으로 계산을 계속하지 않고 새로고침 안내를 표시한다. DB 마이그레이션 완료 후 재시도한다.
- 화면 구조·스타일·추천 점수 계산·경로 제공자는 변경하지 않는다.

## 검증

전체 마이그레이션을 적용한 PGlite에서 실제 익명 RPC를 호출하고, 실제 React 훅과 함께 입력 목록을 렌더링해 테스트한다. 참가자 등록 순서, 오래된 참가자 목록, 진행 중 중복 시작, 만료·재시도, 오래된 완료/실패 응답, 권한 검증, 자신의 초대 링크, 방 전환·새로고침, 오류 안내와 이동수단 유지를 검사한다. 외부 API 응답만 로컬 어댑터로 대체한다.
